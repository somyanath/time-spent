# Time Tracker

A private, local, macOS menu-bar time tracker + focus coach (Rize-style v1). It
passively observes the active app/window/URL, persists an append-only stream of
**Heartbeats** as the single source of truth, and derives every insight on read.
See [`CONTEXT.md`](./CONTEXT.md) for the domain language, [`docs/adr/`](./docs/adr)
for architecture decisions, and issue #1 for the full PRD.

## Status

**Slice 1 — walking skeleton** (issue #16): an Electron menu-bar agent with a
tray, a React/TypeScript renderer showing an empty **Today** surface, and a
SQLite database with a versioned migration runner. No tracking or derivation
yet — this slice proves the process model, tray, renderer, and persistence layer
are alive end to end.

## Stack

- **Electron** (ADR-0003) — main process hosts the tray; a renderer window hosts
  the React/TS dashboard.
- **better-sqlite3** (ADR-0001) — synchronous SQLite under
  `~/Library/Application Support/Time Tracker/`, schema owned by a migration runner.
- **electron-vite** + **Vite** for build/dev, **Vitest** for tests, **pnpm** for
  package management.

## Project layout

```
src/
  main/            Electron main process
    db/            SQLite open + migration runner (the tested seam)
    tray.ts        Menu-bar tray ("Open Dashboard")
    window.ts      Dashboard window
    index.ts       Entrypoint: agent setup, DB init, IPC
  preload/         contextBridge: window.api
  renderer/        React dashboard (Today view)
  shared/          Types shared across the process boundary
test/              Vitest specs
resources/         Tray template icon (generated by scripts/gen-tray-icon.mjs)
```

## Develop

```sh
pnpm install
pnpm rebuild:electron   # build better-sqlite3 for Electron (see note below)
pnpm dev                # launch the agent with hot-reload
```

## Scripts

| Script                  | What it does                                      |
| ----------------------- | ------------------------------------------------- |
| `pnpm dev`              | Run the app with hot reload                       |
| `pnpm build`            | Production build into `out/`                      |
| `pnpm typecheck`        | Type-check main/preload (node) and renderer (web) |
| `pnpm test`             | Run the Vitest suite                              |
| `pnpm rebuild:electron` | Build `better-sqlite3` against Electron's ABI     |
| `pnpm rebuild:node`     | Build `better-sqlite3` against Node's ABI         |

### Native module ABI

`better-sqlite3` is a native module and must be compiled against whichever
runtime loads it. Node and Electron use different ABIs, so switch builds
depending on what you're doing:

- **Running the app** (`pnpm dev` / `pnpm start`): run `pnpm rebuild:electron` first.
- **Running tests** (`pnpm test`): run `pnpm rebuild:node` first.

The repo's committed default is the **Node** ABI, so `pnpm test` works on a fresh
clone without a rebuild step.
